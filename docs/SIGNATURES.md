# Формат базы сигнатур

База — JSON-файл с массивом `rules`. Каждое правило описывает один клиент или
класс модов. Все поля, кроме `id`, `name` и `severity`, необязательны.

## Схема

```json
{
  "schema": 1,
  "updated": "2026-11-04",
  "rules": [
    {
      "id": "nursultan",
      "name": "Nursultan",
      "severity": "high",
      "description": "RU-чит-клиент для анархии",
      "filenames": ["nursultan*.jar", "*nursultan*.jar"],
      "sha256": [],
      "jar_prefixes": ["nursultan/", "ru/nursultan/"],
      "processes": ["nursultan*"]
    }
  ]
}
```

| Поле | Тип | Обязательное | Что означает |
| --- | --- | --- | --- |
| `id` | строка | да | Уникальный идентификатор, латиницей |
| `name` | строка | да | Отображаемое название |
| `severity` | `low` / `medium` / `high` | да | Уровень важности находки |
| `description` | строка | нет | Пояснение для отчёта |
| `filenames` | список шаблонов | нет | Сопоставление с именем JAR, регистр не важен |
| `sha256` | список хэшей | нет | Точные хэши конкретных сборок |
| `jar_prefixes` | список префиксов | нет | Пути записей внутри JAR |
| `processes` | список шаблонов | нет | Имена процессов без `.exe` |

Шаблоны — обычные glob-выражения (`*`, `?`, `[...]`), как в `fnmatch`.
Префиксы JAR сравниваются с началом имени записи, например
`meteordevelopment/meteorclient/MeteorClient.class`.

## Приоритет проверок

Для одного файла правило срабатывает один раз, в таком порядке:

1. содержимое JAR (`jar_prefixes`);
2. SHA-256 (`sha256`);
3. имя файла (`filenames`).

Поэтому переименованный клиент всё равно находится по структуре классов,
если разработчик не перепаковал архив.

## Как добавить правило

1. Убедитесь, что клиент реально существует и вы не добавляете вымышленное имя.
2. Укажите минимум один способ обнаружения: `filenames`, `jar_prefixes` или `sha256`.
3. Для `high` используйте только клиенты, чьё основное назначение — читы.
   Моды вроде Baritone или X-Ray помечайте `medium`.
4. Добавьте запись в `signatures/cheats.json` и запустите тесты:

```bash
python3 -m unittest discover -s tests -v
```

5. Проверьте, что база валидна:

```bash
python3 -m rwcd rules
```

## Про хэши

`sha256` — самый точный способ, но он привязан к конкретному файлу. Добавляйте
хэш только той сборки, которую проверили вручную, и указывайте версию в описании.
Хэш не должен быть единственным признаком: обновление клиента его сломает.

## Чего в базе быть не должно

- Персональных данных: ников игроков, почт, IP-адресов.
- Ссылок на скачивание клиентов.
- Правил, которые срабатывают на ванильные файлы Minecraft.
- «Правил-заглушек» без реального признака обнаружения.
